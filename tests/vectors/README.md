# Test vectors

Fixtures are **literal bytes** (rule R1) and expected decodes are **literal
text** (rule R2). Nothing in this directory is generated by the decoder, and
nothing here may be produced by calling into the decoder's own naming or
formatting functions — that would turn a test into a tautology.

Where a hand-written fixture needs a fresh CRC byte, generate it with the
out-of-tree tool and paste the result as a literal:

    ./tools/crc_ref.py 21 00 20

## `espi_dump.txt`

857 lines of an eSPI link coming up, exported from a third-party decoder
against real hardware. Provenance beyond that is unestablished — see the open
questions in the plan.

This is the most valuable file in the suite: it is the only evidence produced
by an implementation entirely independent of ours. Ten CRC vectors transcribed
from it are the sole independent confirmation that our CRC covers the right
byte spans, in particular that the response-phase CRC includes the two STATUS
bytes.

Column layout is undocumented — eight signal columns under six headers. Only
the timestamp, the trailing label and its parenthesised byte value are relied
upon, and those are unambiguous.
